# H743 双目 / IMU 独立上位机

> **电脑接收时间统一，曝光同步误差未验证。** 本程序不能在不增加硬件同步、不了解曝光时序的情况下，保证图像曝光时刻与 H743 采样时刻完全一致；左右目曝光同步也未经验证。

## 隔离与安装

所有源代码、测试、启动脚本、虚拟环境、默认保存目录均位于本目录。程序不导入固件或原有 tools，不需要固件构建产物。默认只接收数据；仅在用户明确确认“重新校准 IMU”后发送一次重校准命令，改变板端当前融合状态；不烧录固件或修改持久配置。解析器独立支持本次升级的 IMU2 v3 六轴/姿态帧和执行 ACK，同时保留 v2 离线兼容。依赖：Python 3.11、PySide6、PyQtGraph、OpenCV、NumPy、pyserial；psutil 用于进程内存观测。

从仓库根目录打开 PowerShell：

~~~powershell
cd .\viewer
.\setup.ps1                 # 首次安装，Python 3.11
.\run.ps1                   # 启动 GUI
# 也可双击 run.cmd
.\run.ps1 devices           # 只列举 USB 身份与相机 PnP 信息
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
~~~

若 PowerShell 策略阻止脚本，可单次使用 powershell -ExecutionPolicy Bypass -File .\run.ps1，不需要永久修改系统策略。setup.ps1 支持 -Python 参数指定 Python 3.11 可执行文件。安装需要网络；运行、测试和保存不需要网络。

## GUI 操作

1. 刷新设备，选择 CAFE:4011 的 H743；按 USB 序列号核对设备，不依赖 COM12 固定编号。
2. 默认相机索引 0、MSMF、MJPG、2560×720、请求 30 fps。左右半幅各 1280×720；采集后核验实际图像形状，速率由实际主机交付时间跨度测量，不以属性值代替实测。
3. 点击 **连接预览**：设备打开后立即显示双目图像和六轴曲线；切换 **姿态** 页可查看有效状态、三角度、四元数和连接全程波形，以及实测速率、质量标志、CRC、序号缺口和电脑接收时间诊断。此时在内存中保留本次连接的波形历史（最近 10 秒完整样本，更早为分段峰值，详见下节），**不创建会话、不写盘、不要求选择有效保存目录**。
4. 需要保存时，在 **设备 / 保存设置** 中选择一个 **保存位置**（默认 `viewer/recordings/`），再点击 **开始录制**；每次录制创建独立的 `session_…/raw/`，保存全部 IMU 与原始彩色双目图像。波形的显示压缩不影响磁盘中的完整原始数据。
5. 点击 **完成录制**：程序排空写盘队列、关闭文件，直接生成时间索引和 **`raw/imu_image.csv` 六轴／图像／姿态关联表**。立即弹出非阻塞的 **正在保存** 小窗口，成功后自动关闭，主窗口保留保存路径；相机、六轴和姿态预览继续。仅显示不定进度动画，不虚报百分比。**不再执行自动导出，不再提供导出、重新导出或重试导出按钮，不创建 `export/` 或灰度图副本。**
6. 保存失败时显示 **保存失败**、原因及已写入目录；错误提示可关闭，已写文件不删除，但数据或关联表可能不完整。正在保存时不能关闭进度提示或重复开始录制；保存结束后可继续录制。录制中断开连接或关闭主窗口仍先安全停止、排空写盘并完成保存；关闭主窗口会等待设备与写盘线程，请勿强杀进程。磁盘保存故障不会主动关闭正常预览；设备异常则明确报错并停止连接。

相机 PnP 清单与 OpenCV 索引不是权威一一映射；请用预览核对。MJPG 是请求值，后端报告的 FOURCC 可能并非真实传输编码，程序保存报告而不宣称编码已验证。实时预览与录制保存独立；首版仍不提供离线回放。连接操作同时打开相机和 H743，不是仅打开相机的独立模式。

## 布局与图像显示

- 默认 **自适应布局**：窗口达到 1250×780 Qt 逻辑像素时，左侧上下显示 cam0/cam1，右侧上下显示加速度／角速度；较小窗口改为上方双目并排、下方两张波形并排。此阈值不是相机分辨率或物理屏幕像素。
- 顶部可手动选择 **左右分区／上下分区**。相机与波形之间、两张波形之间均可拖动分隔条调整比例。切换布局不清空历史、不重置当前查看范围或实时跟随状态。
- 双目预览从原始拼接帧分别绘制两半幅，各自按比例完整适配，**不拉伸、不裁切**；保留必要留白。调整窗口大小后即使没有新图像到达，也会重新适配显示。
- **设备 / 保存设置** 可折叠相机参数和保存目录；**诊断 / 日志** 默认折叠，可展开查看设备／写盘／接收时间详情和事件日志，避免挤占预览与波形空间。
- 实际速率、CRC／缺号、质量标志始终显示；录制时还显示队列与磁盘余量。连接／录制异常使用独立红色提示，即使详情折叠或设备已断开也可见。
- 以上只调整显示布局，**不改变原始采集分辨率、保存图像、USB 协议或时钟对齐算法**。cam0/cam1 仍对应输入左右半幅，物理目序及左右目曝光同步未标定。

## 波形交互与本次连接历史

### 操作方法

- 相机与波形之间、加速度与角速度之间均可拖动分隔条调整空间；默认给波形区较大空间。加速度为 g，角速度为 °/s，X/Y/Z 三轴分别显示。
- **滚轮**：以鼠标位置为中心缩放时间轴；**左键拖动**：平移查看历史。普通时间轴滚轮不关闭纵轴自动缩放，后续数据幅值变大时仍会自动适配。
- **Shift+滚轮**，或将鼠标放在纵轴刻度区滚轮：独立缩放该图的纵轴；纵轴区也支持拖动。**两个图的时间范围联动，纵轴独立**，移到独立窗口后仍保持联动。
- **时间窗**：手动输入横轴显示时长，默认 10 秒，可设 **0.001–86400 秒**，输入后按 Enter 或移开焦点生效。例如改为 `0.1 s` 或 `1 s` 观察短时变化。实时跟随时窗口跟随最新数据；历史查看时以当前视图中心调整宽度，不跳回实时。主窗口和独立大图共享此设置，两图横轴保持联动。滚轮／拖动只改变当前视图，不覆盖此预设；“回到实时”使用所设时间窗，“查看全程”仍显示全部历史。
- **纵轴范围…**：分别设置加速度（g）和角速度（°/s）的下限、上限，勾选对应的 **固定纵轴（实时／历史均保留）** 后点击 **应用**。下限必须小于上限；未勾选的图恢复自动。显式固定范围在实时跟随与历史查看中均有效，应用设置不退出实时跟随。例如可将加速度设为 `0.98–1.02 g`、角速度设为 `−0.5–0.5 °/s`，但范围外的轴或峰值会被裁切；这只是显示范围，不是提高传感器精度。
- 手动滚轮缩放、拖动或点击 **查看全程** 后暂停实时跟随，**不暂停采集或录制**。点击 **回到实时** 恢复所设时间窗，并将未显式固定的纵轴恢复自动；通过“纵轴范围…”显式固定的纵轴仍保留。查看历史时默认继续按可见时间区间自动适配幅值；主动用 Shift+滚轮或纵轴区滚轮／拖动调整幅值后，该图保持手动纵轴。后续时间导航不撤销手动范围。
- 每张图分别显示 **纵轴自动／纵轴手动／纵轴手动（固定）**，独立大图也保留状态。普通鼠标纵轴操作会退出实时跟随，“回到实时”解除这种临时手动范围；显式固定范围须点击 **纵轴自动** 或在范围对话框取消勾选并应用来解除。“纵轴自动”恢复两图自动，但不改变时间范围或实时／历史状态。新连接成功后恢复实时和两图纵轴自动，保留已选择的时间窗；这些显示设置不跨程序重启保存。
- 状态栏显示当前查看范围、历史总时长、样本数、实时跟随／历史查看、完整样本／分段峰值、历史内存及容量告警。
- **双击任意波形**：将该图移入普通独立窗口，默认在主窗口所在屏幕居中显示，不自动全屏或半屏；可拖动、调整大小，并使用系统标题栏的 **最小化／最大化／关闭** 按钮。主窗口保留占位提示，相机预览、采集和录制继续。独立窗口保留时间窗、纵轴范围、实时／历史等波形控制，工具栏首位为 **返回主窗口**，不再提供普通窗口、全屏或左右半屏按钮；最大化与还原通过系统标题栏操作。最小化不将图恢复到主窗口；关闭独立窗口只恢复图，不停止采集。
- 在独立图中再次双击、按 **Esc**、关闭独立窗口或点击主窗口占位提示，都会将图恢复到主窗口，保留当前时间和幅值范围。关闭主窗口仍先执行原有安全停止和写盘收尾流程，不应强杀进程。

### 历史生命周期与精度限制

**波形历史不等于录制文件。** 历史仅在内存中保存：

1. 从本次连接开始保留，未开启录制也能回看；开始／停止录制均不清空历史。
2. 断开连接后保留，仍可缩放查看；下一次连接成功、相机和 IMU 均输出数据后才清空旧历史。未成功输出两路数据的连接尝试不清空旧历史。
3. 程序退出后内存历史消失；本版不提供录制文件回放，也不增加图像逐帧联动。

可调时间窗只影响显示，**不会改变最近 10 秒完整历史的保留策略**；即使选择更窄窗口，早期压缩细节也不能恢复。最近 **10 秒**保留完整整数时间戳和原始六轴样本；更早部分依据 H743 时间按 **30 Hz（约 33.3 ms）**分段，逐轴保留首值、最小值、最大值和末值及其真实 H743 时间。摘要持续维护，不依赖 GUI 每 100 ms 刷新，也不依赖相机帧率或时钟映射。每轴峰值独立，**不将不同时刻的极值拼成一条虚假的六轴样本**。

绘图根据可见时间范围和像素宽度再选取最小／最大包络，不用简单间隔抽点舍弃尖峰。**早期历史可查看峰值和趋势，但放大不能恢复已舍弃的原始细节。** 早期分段内的变化不能当作完整原始轨迹；如需完整数据，应提前开启录制并查看会话内全部 IMU 原始数据。序号缺口、无效数据和时间异常处断线，不插值伪造连续性。

横轴仍是相对本次连接首个样本的 **H743 时间**，不是相机曝光时间，也不是保存表中的电脑接收时间。波形历史不使用新的统一时间重写横轴；原始六轴的保存、轴定义和原有波形处理不因姿态页改变。当前保存和图片关联统一使用电脑读取完成时间，详见下节。

### 内存与后台绘制

历史使用分块 NumPy 数组，采集路径按完整解析批次追加，绘图在独立后台线程计算，仅保留最新待处理视图请求。固定的旧历史视图不随每个新样本重算，同一大范围视图的新数据刷新限至约 1 Hz；导航和尺寸改变会触发新请求，过期请求会合并。完整一小时概览的曲线计算可能超过 100 ms，但不在界面线程内执行。

原始六轴历史与姿态／四元数历史各自的存储及索引采用 **128 MiB 安全上限**，达到上限或历史分配失败时明确冻结全程摘要，并显示摘要截止时间；不静默覆盖旧历史，最近实时窗口和独立原始录制继续。**128 MiB 不是整个进程 RSS 限额**，不包括 Qt、相机图像、写盘队列和临时渲染数组；整进程内存耗尽等系统性故障无法保证正常运行。每套历史的最近完整窗口均有 4 MiB 预留（已包含在各自预算内），远超约 1 kHz 的需求；异常高输入速率使完整窗口不足 10 秒时会明确告警。

## 姿态显示与录制详情

- **原始六轴 / 姿态** 页签切换不影响采集与录制。姿态页显示有效／校准中／无效／中断／旧 v2 无姿态状态，以及 roll、pitch、yaw（度）和 qw、qx、qy、qz。
- 姿态来自板端，机体 **FRD** → 世界 **NED**，四元数标量在前，Euler 3-2-1。无 BMM150，yaw 在静置校准时归零并允许漂移，不代表真北。融合安装旋转暂定 X/Z 取反，**尚未实板确认**，原始六轴仍为芯片寄存器轴。
- 姿态页复用原始六轴的交互组件，分别显示 **欧拉角 roll／pitch／yaw 三条曲线（°）**、**四元数 qw／qx／qy／qz 四条曲线（无量纲）**。两个图的时间轴联动、纵轴独立；姿态页与原始六轴页的查看范围和跟随状态各自独立。
- 支持 **滚轮缩放时间、左键拖动回看、Shift+滚轮或纵轴区滚轮缩放幅值**，以及 **回到实时、查看全程、纵轴自动、纵轴范围…、时间窗（0.001–86400 s）**。自动／手动／显式固定纵轴的行为与原始六轴一致：回到实时恢复临时手动纵轴的自动适配，显式固定范围仍保留。
- **双击任意姿态波形**打开普通独立窗口，可用系统标题栏最小化、最大化、关闭；窗口内保留“返回主窗口”和同款波形控制，不提供全屏／半屏功能按钮。再次双击、Esc、关闭或点击“返回主窗口”恢复原位置与当前范围；采集及录制不中断。
- **从本次设备连接开始保留波形历史**，未录制也可回看，录制开始／结束不清空；断开后保留，新连接成功后清空。最近 **10 秒**保留完整浮点姿态值与整数 H743 时间，更早按 **约 33.3 ms** 保留各分量首值／最小值／最大值／末值及其真实时刻。后台按可见范围和像素宽度绘制峰值包络，不再受旧界面 10,000 点趋势队列限制。波形历史仅在内存中，不等于录制文件；放大早期历史不能恢复已舍弃细节。
- **四元数摘要是各分量独立峰值，不是同一时刻的归一化四元数，不可作为姿态解算输入。** 不对源四元数改符号、归一化或修改姿态解算。校准、无效、序号／时间／会话异常、任意欧拉角跨 ±180° 或相邻四元数符号翻转时断线，不将占位值或表示跳变连成有效轨迹。时间回退明确告警，不伪造新的连续时间轴。
- 超过 **0.1 秒**无更新或断开时清空当前有效数值显示；恢复后的缺口不插值。已测历史仍可查看。原始保存、关联、统一电脑接收时间及姿态数值语义均不改变；图中横轴仍是本次连接相对 H743 时间。
- 原始六轴曲线按其自身质量标志工作，校准/姿态无效不自动清空正常原始轴。磁航向辅助、拒绝或参考状态（`0x2000 / 0x4000 / 0x8000`）也不屏蔽原始六轴。传感器 SPI、数据过期、DRDY、缓冲溢出或历史缺失等原始质量错误仍按无效样本处理并断线；此过滤只影响波形显示，不删除原始录制数据。
- 在 **诊断 / 日志** 中点击 **录制姿态详情…**，选择已完成录制的会话目录，按 **256 行/页**查看姿态有效性、四元数及角度。无效/v2 以破折号显示，不是完整离线回放；数据完整性请执行 verify。

> 本功能未完成完整 v3 实板验收；历史 v2 的长测不能证明 76 kB/s、板轴或融合正确。发布前检查要求见 [协议文档](../docs/protocol.md#验证边界)。

### 手动重新校准 IMU

连接并收到 IMU 数据后，点击 **重新校准 IMU**，将板卡放稳并确认（默认“否”）。按钮不依赖相机首帧；等待操作完成期间禁用重复请求。确认后弹出独立的非阻塞校准窗口，显示发送、等待确认和静置状态；相机、原始六轴与录制继续。只有收到执行边界之后的有效姿态才显示“校准完成”，保留 **1 秒** 后自动关闭。确认超时、连接中断或请求失败时不自动关闭，显示原因、放稳提示及 **重试校准**；仅在连接已就绪且没有执行中请求时可手动重试，不自动重发。断开后须先在主窗口重新连接。关闭提示不取消板端校准。

- 不复位 MCU、不重开串口、不暂停原始六轴或录制。重新估计陀螺零偏和重力倾角，完成后 **相对 yaw 重新归零**；旧航向基准不能直接拼接。
- 状态依次为排队、已发送等待执行确认、板端已执行并等待静置、姿态有效后完成。**执行 ACK 不是校准完成**；旧积压数据不会提前完成操作。理想连续输入下约需静置 2.2 s，运动会重新累计。
- 从用户确认开始，当前姿态数值遮蔽、趋势断开；旧历史、原始六轴及原始 CSV 保留。板端真正无效期间的姿态 CSV 留空，不对过去测量追溯改值。
- ACK 等待 3 s 超时显示“结果未知”，不自动重发，匹配的迟到 ACK 仍可恢复状态；旧固件可能不支持命令，需升级板端。ACK 后超过 30 s 仍在等待有效姿态则提示继续静置，不自动重复重置。
- USB 断开后不自动补发；正常重连不重置姿态。该功能只改变本次 RAM 中的融合状态，不保存掉电校准参数。

`usb.bin` 保存控制 ACK；传感器 CSV 不增加控制行。`session.json` 说明相对航向与手动校准语义，`events.jsonl` 记录操作状态、实际重置边界、新 yaw 参考首次有效时间及开始录制时的控制上下文。离线校验仍从原始 USB 对照传感器 CSV。详细方法见 **[IMU 校准说明](../docs/imu-calibration.md#21-从上位机手动重新校准)**，线协议见 [控制协议](../docs/protocol.md#手动重校准控制v132-字节)。

## CLI

以下 SESSION 可使用总会话文件夹、其中的 `raw/`，或旧版原始会话目录。通过 `--output` 指定保存根目录，每次录制新建 `session_…/raw/`；录制结束直接保存关联表，**没有 export 子命令**。

~~~powershell
.\run.ps1 record --seconds 605
.\run.ps1 record --serial-number YOUR_USB_SERIAL --camera 0 --output .\my_capture --seconds 605
.\run.ps1 verify SESSION                  # 原始 USB 重解码、CSV/模型/图像审计
.\run.ps1 verify SESSION --decode-all     # 另逐张解码全部彩色 PNG
.\run.ps1 finalize SESSION                # 已停止会话：重建时间索引与图片关联表
~~~

CLI 返回 0 表示命令成功，2 表示采集、保存或校验错误。在采集阶段按 Ctrl+C 会停止并排空写盘、保存关联表；请等保存完成后退出，不要再次中断或强杀。600 秒计时包含设备启动，若要求实际相机跨度 ≥600 秒，应使用 605 秒并检查 quality/verification 报告。

`finalize` 拒绝 state=recording 的活跃或意外中断会话，避免与写盘竞争；它不是录制文件回放，也不能补回未写入的数据。不提供自动修复崩溃会话或篡改状态的快捷命令，请保留原始文件调查。重新连接或 MCU 重启必须创建新会话，不跨重启拼接。旧会话原模型与原始字段保持原语义，新增关联表使用已保存的主机接收时间。

## 原始协议与单位

串口以兼容参数 115200、DTR=True 打开，无新增同步应答，无 write() 命令。独立解析 **IMU2 v3/type 3、76 字节、小端、CRC32（前 72 字节）**，保留 IMU2 v2/type 3、48 字节（CRC 覆盖前 44 字节）离线解析。支持混合版本和任意拆粘包、坏帧后重同步；解析缓冲小于 4096 字节。参考向量保存在测试中；运行不依赖仓库其他目录。

imu.csv 每条 CRC 有效合并帧保留 sample_id、batch_id、sequence、timestamp_us、timestamp_ns、ax_raw/ay_raw/az_raw、gx_raw/gy_raw/gz_raw、accel_age_us、gyro_age_us、flags、tick_late_us。timestamp_ns 仍表示 H743 时间，用 Python 整数 timestamp_us ×1000，避免浮点损失；新增 unified_timestamp_ns 表示电脑读取完成时间，不覆盖原时间。另列 accel_time_us/gyro_time_us=共同时间减样本年龄。新增 protocol_version、attitude_valid、qw/qx/qy/qz、roll_deg/pitch_deg/yaw_deg；**无效或旧 v2 的姿态数值列为空，attitude_valid=0**。接收端检查标志、源时间、有限数和四元数归一化，不把占位数值当测量。

名义换算：加速度 raw ×24/32768 g；角速度 raw ×2000/32768 °/s；SI 使用 9.80665 m/s²/g 和 π/180 rad/degree。**原始六轴**顺序 x/y/z 原样，不扣零偏、不旋转；板端另用独立安装旋转和校准零偏计算姿态，二者不能混淆。共同输出网格不表示加速度和角速度在物理上同时转换；样本年龄字段不可忽略。

flags 位：0 输出时序异常，1 加速度 SPI 错误，2 陀螺 SPI 错误，3 ring 溢出，4 新会话，5 加速度陈旧，6 陀螺陈旧，7 加速度 DRDY 异常，8 陀螺 DRDY 异常，9 历史缺失，10 校准中，11 姿态有效，12 融合重置。flags 原始整数也保留，未知位不删。CRC 错误与序号缺口显式计数；时间回退、序号重复/回退、会话变更会停止录制。

## 统一时间：电脑接收时间，不是曝光同步

### 当前方案与原始时间

新录制会话采用 **schema 3**（增加协议和姿态元数据，接收时间方案不变），`timestamp_basis=host_receive`。图像与 IMU 的统一时间均为 **`perf_counter_ns()` 在各自 `read()` 返回后紧邻采集的 `host_read_end_ns`**，保存为整数纳秒 `unified_timestamp_ns`。不再将图像映射到 H743 时间轴，不做偏移／漂移仿射拟合，不等待 2 秒建立时钟模型（与板端约 2.2 秒静置姿态校准无关），也不按模型有效区间筛掉图像。

这里的“到达电脑”具体指**应用程序读取完成**，不是 USB 总线上物理到达时刻、传感器采样或曝光时刻。驱动缓冲、USB 传输、操作系统调度及两路读取方式不同带来的延迟仍存在，没有被辨识或消除。统一时钟并不意味着两路在物理上同步。

| 时间字段 | 含义与用途 |
| --- | --- |
| IMU `timestamp_us` / `timestamp_ns` | 原始 H743 共同输出时间，纳秒由整数微秒乘 1000；保留用于分析采样间隔和样本年龄 |
| 图像 `camera_media_ms` / `camera_media_ns` | 原始后端媒体时间；时钟域与曝光语义未验证，不参与当前统一时间计算 |
| `host_read_start_ns` / `host_read_end_ns` | 相机或串口每次读取的电脑单调时间区间 |
| `unified_timestamp_ns` | 该条数据所属读取的 `host_read_end_ns`；保存和关联使用的统一时间 |

系统日期时间仅用于会话命名。`perf_counter_ns()` 不是 UTC；不得把不同电脑、不同系统启动周期的数据当作共享绝对纪元直接合并。设备重连或 MCU 重启仍需另建会话。

### USB 批次与重复时间戳

每次非空 USB read 作为一个 batch，保存原始字节偏移、长度、读取起止时间和解码帧数。**同批所有完整 IMU 帧共享该批读取结束时间**；跨读取拆开的帧归入完成解码的那个批次。没有完整帧的读取仍保留批次和原字节。

不为同批 IMU 插值生成不同到达时间，不人为递增 1 ns，也不复制相机时间到 IMU。重复接收时间是批量读取的真实记录，不表示 MCU 重复采样。相机两目从同一拼接图拆分，共享该帧接收时间，这不证明左右目曝光同步。

相机媒体时间缺失、重复或回退只作为诊断计数，原样保留，不再因其无法拟合而停止正常的主机时间录制。主机读取区间非法或回退、H743 时间异常等仍显式报错；不静默生成貌似有效的替代时间。

### 最终化、校验与旧会话

- 停止录制后排空写盘，再从保存的 USB 批次和图像索引生成统一时间索引；`verify` 会重解码 USB，并核对每条 unified 时间与所属读取结束时间一致。
- 新会话 `clock_models.json` 中 `timestamps_valid=true`、`models_valid=false`、`models={}`、`clock_fitting_used=false` 表示**直接使用接收时间，不需要拟合模型**，不是模型失败。`clock_residuals.csv` 仅保留表头，不再生成拟合残差。
- schema 2 旧会话缺少姿态列时仍可校验；不对 v2 数据补算或伪造姿态。
- schema 1 旧会话仍保留原来的拟合文件和审计方式；使用当前程序重建关联表时，采用其已保存的电脑读取结束时间，不依赖旧模型有效区间，不覆盖源会话的 MCU 或媒体时间。
- 原始时间和接收时间并存，波形横轴仍用相对连接起点的 H743 时间，不等同于保存表的接收时间。

**限制声明：电脑接收时间统一，曝光同步误差未验证。** 不保证固定传输延迟已校正、不保证 IMU 采样与图像曝光同时、不保证左右目曝光同步。图像关联容差也不是同步精度。

实现入口：`imu_viewer/timing.py`（批次时间与稀疏匹配）、`capture.py`（读取观测）、`storage.py`（保存／最终化／关联）、`verify.py`（原始审计）。`clock.py` 仅保留用于旧会话和旧模型测试，不参与新会话的统一时间计算。

## 保存文件结构说明

操作流程为 **开始录制 → 完成录制 → 保存完成**，不再额外导出。保存完成时已经包含原始六轴、图片关联、四元数／欧拉角和完整时间字段。只需选择一个保存根目录，所有内容在同一个总会话文件夹内（名称为示例）：

```text
viewer/
└── recordings/
    └── session_20261120_140000_123456/
        └── raw/
            ├── imu_image.csv       # 以每条 IMU 为主的全量关联表
            ├── association.json    # 关联规则、数量、列分组与限制
            ├── imu.csv             # 全量原始六轴、姿态、时间及质量字段
            ├── frames.csv          # 全部已提交双目图像索引
            ├── cam0/               # 原始彩色 PNG
            ├── cam1/
            └── …                   # USB 字节、配置、时间索引及质量记录
```

完整目录树、字段、空值规则、归档和异常检查方法，见 **[保存文件结构说明（DATA_LAYOUT.md）](DATA_LAYOUT.md)**。

`imu_image.csv` 按 **原始六轴 → 图片信息 → 四元数／欧拉角 → 时间与补充信息** 排列，所有 CRC 有效 IMU 行保留；缺图片只留空图片栏，缺有效姿态只留空姿态数值栏。旧版本已有的导出目录不删除，但新录制不再生成。

## 会话文件

下列文件均位于新格式总会话文件夹内的 `raw/`；图像索引及关联表中的相对路径均以 `raw/` 为基准。归档时请保留整个总会话文件夹。

| 文件 | 内容 |
| --- | --- |
| session.json / devices.json | 配置、生命周期、USB 身份、相机清单/后端、限制说明；schema 3 记载 IMU 协议、FRD/NED、四元数方向、Euler 单位、相对航向及安装旋转待核验语义 |
| usb.bin / usb_batches.csv | 原始收到的 USB 字节及每次非空读取批次索引 |
| imu.csv | 全部 CRC 有效帧、H743 原始时间、unified_timestamp_ns、原始值、年龄、质量、名义换算及姿态有效性/四元数/角度 |
| imu_image.csv / association.json | 全量 IMU 主表及可为空的图片关联、同帧姿态、原始与统一时间；关联规则与数量见下节 |
| cam0/*.png / cam1/*.png | 左右彩色无损 PNG，以 frame_id 命名 |
| frames.csv | 原始媒体时间、主机读取区间、unified_timestamp_ns、尺寸、双目文件对应关系 |
| aligned_frames.csv | 新会话为 unified_timestamp_ns 及 host_receive_time 状态；不覆盖原索引 |
| clock_models.json / clock_residuals.csv | 新会话的接收时间方案声明与表头空残差表；旧会话为原模型与残差 |
| quality.json / events.jsonl | 实测速率、连续性、内存/队列/磁盘遥测、故障 |
| failure.json（必要时） | 最终化等失败记录 |
| verification.json（verify 后） | 原始 USB/CSV 重解码、模型复算和 SHA256 审计 |

GUI 在同一次连接内可多次录制，各会话的 USB batch_id、图像 frame_id 从 0 开始；每次录制只独立解析实际进入该会话的 USB 字节，不借用录制前的预览半帧。起始不完整帧前缀计入 parser.bytes_discarded，尾部不完整帧计入 trailing_bytes，原始字节均保留。

session.json 的 stopped / stopped_error 是最终状态；quality 中 done 是最终化前的快照，可能为 false，不代表后台仍运行。尾部不足一帧（v3 为 76 字节、v2 为 48 字节）可能是正常停止时的读取边界，字节仍保留并报告，不伪造解码帧。

## 有界采集与故障语义

串口、相机、写盘、PNG worker、GUI 分离；默认 USB 队列 1024 项、图像队列 64 帧、PNG 并发 8、在途任务最多 32；显示曲线/模型/遥测也有上限。队列上限约束内存，不保证所有磁盘都足够快。

队列溢出明确记录 rejected 计数和“当前项未保存”，停止生产并排空已接收项；写盘失败可能无法排空，剩余队列和未提交任务明确报告，不声称数据完整。双目都成功写入后才提交图像索引，失败可能遗留未索引的孤儿 PNG。USB 无数据 3 秒、相机启动 15 秒/交付中断 3 秒触发异常；端口占用、断开、读失败或磁盘低于默认 1 GiB reserve 均明确停止。GUI 点击“完成录制”仅停止保存，继续预览；CLI 停止录制、GUI 断开连接或关闭窗口时才关闭设备。原生驱动若不可中断地阻塞，10 秒线程等待/60 秒写盘等待会报告超时，但不能保证强行释放挂死驱动。

本机场景 10 分钟彩色双目 PNG 约需 **34 GB**，复杂场景可能更多。保存收尾不再解码、复制或重新编码图片，但仍需等待已有 PNG 任务、写盘队列、CSV 关联表与文件同步完成。1 GiB reserve 只是运行保护，不是完整会话容量预测。CSV/raw 关闭时 flush+fsync，元数据临时文件替换；PNG 普通文件关闭，**不保证断电事务原子性**。故障数据不自动删除。

## 保存关联表、空值与追溯

### `imu_image.csv`：以六轴时间为主，每条 IMU 都保留

保存完成时直接生成该表，**每条 CRC 有效合并 IMU 帧一行，绝不只保留匹配成功的行，也不按相机频率降采样**。列分为：

1. 原始六轴：`ax_raw, ay_raw, az_raw, gx_raw, gy_raw, gz_raw`。
2. 图片信息：`image_frame_id, image_timestamp_ns, image_minus_imu_ns, cam0, cam1`。
3. 姿态：`qw, qx, qy, qz, roll_deg, pitch_deg, yaw_deg, attitude_valid`。
4. 其余全部源 IMU 字段：`sample_id`、`batch_id`、`unified_timestamp_ns`、H743 `timestamp_us/timestamp_ns`、序号、协议版本、年龄、质量及物理量等。

**每行使用该条六轴自己的时间戳，不用图片时间替换。** 保持此前约定：统一时间 `unified_timestamp_ns` 为该 IMU 完成解码所属 USB 批次的电脑读取结束时间；原始 H743 微秒时间及整数乘 1000 的纳秒时间并列保留。批次中多条 IMU 的统一时间可以相同，不插值、不人为递增。

| 情况 | 保存规则 |
| --- | --- |
| 无对应图像 | 五个图片字段全部为空；六轴、时间戳和已有有效姿态不变 |
| 无有效四元数／欧拉角（含 v2、校准中等） | 七个姿态数值字段为空，`attitude_valid=0`；六轴、时间戳和已有图片关联不变 |
| 图像和姿态都缺失 | 两组分别留空，仍保留六轴整行 |
| 匹配到图像 | 两目路径指向原始彩色 PNG，如 `cam0/000000000.png`，相对于 `raw/` |

四元数及欧拉角来自**同条 H743 IMU 帧**，不是由图片计算、重采样或插值得到。非常旧的源会话如果没有姿态列，不凭空补算姿态；当前录制即使使用 v2 也有相应空列。

### 关联规则与限制

保持现有关联规则不变：按相机帧顺序，在 **20 ms** 接收时间容差内选择最近的**尚未匹配 IMU**，一对一；等距选择较早 IMU，同批同时间选择较早 sample_id。这是顺序贪心规则，不是全局最优，也不是曝光同步。不会将同一图像填到所有高频 IMU 行中。

`image_timestamp_ns` 为图像读取结束时间，`image_minus_imu_ns` 为图像减去 IMU 接收时间的有符号纳秒差。所有未匹配图像仍保留在 `frames.csv` 与两目目录，不会凭空生成无 IMU 的表行。`association.json` 记录时间方案、关联规则／容差、全部 IMU 行数、匹配／未匹配数量、图片数量、列分组及限制。

`imu.csv`、`frames.csv`、`usb.bin` 和原始彩色图不因关联而改写。收尾仅读取索引与 IMU CSV 生成关联表，**不进行图片二次解码／编码，不生成灰度图、EuRoC 目录或重复图片副本**。关联表用临时文件写入并原子替换，失败不标记最终化成功。默认不逐张复查全部图片，需要时单独执行 `verify --decode-all`；保存成功不等于全量离线审计已完成。

不生成虚假内参、外参或标定文件。本版仍不含在线 VIO、完整录制文件回放、图像逐帧联动或曝光同步精度保证。**电脑接收时间统一，曝光同步误差未验证；关联容差不是同步精度。**

## 验收

同目录 ACCEPTANCE.md 保留历史实测、失败尝试和未验证事项，不代表新增固件已烧录或已通过实板验收。本功能的验收边界见 [协议文档](../docs/protocol.md#验证边界)；本轮验证报告与采集数据仅在本地保留。单元测试包括协议向量、拆粘包、CRC、回绕、时钟漂移/固定延迟、写盘/设备故障注入、全量保存关联及 GUI 无硬件测试。故障注入不等同于实际物理拔插。
